Owner goal: iormesh is easy to
install and use for a less capable agent — Claude Sonnet 5.5 at
medium effort (`claude -p`) and glm-5.3-flash (the `pi` coding
agent, ollama cloud) — working from the docs and an iormesh
skill alone. The decision, with every number and its reasons, is
[decisions.md #37](../decisions/decided/tracing-docs-agents.md); this
section says what lands and what accepts it.

- **The iormesh skill** (task om4): `docs/skills/iormesh/SKILL.md`,
  written by the skill-maintenance skill's rules, loadable by
  Claude Code and pi; the operator installs it by copying or
  linking the folder into the agent's skills directory (#37
  names both). Before every step it explains the host, the
  commands, what they change and what data leaves the machine,
  and waits for approval; at the start the user picks automatic
  or guided mode. It points into [the guide](../guide/README.md)
  for the path and does not re-teach it.
- **The trial harness** (task mm4): runs one agent in one mode
  against the throwaway iom VMs on f3 (Rocky 9.9) — `iom1` the
  controller, `iom2` the traced host running the test workload's
  microservices scenario — with the agent's only shell on the
  VMs, never on the laptop. It prepares the VMs as #37 lists,
  hands the agent the fixed task prompt, the questions, and a
  copy of README.md, `docs/guide/` and the skill, plays the
  scripted user (mode choice, approvals, guided paste-back),
  enforces the turn and time budget, scores the answers and
  writes the result and the transcript under
  `eval/agent-trial/`. Its inputs live there too:
  the task prompt and a question set of ten questions, answers
  known from the scenario's declarations and held by a test,
  pinned before the first run. Built: `internal/agenttrial`,
  `mage agentTrial`; how it runs, its sandbox and its tests are in
  [testing/agent-trial.md](../testing/agent-trial.md).
- **The trial** (task nm4): the four acceptance cells below, on
  one commit; each failure filed as a task.

## Acceptance

All four cells — Claude Sonnet 5.5 medium and glm-5.3-flash, each
in automatic and in guided mode — pass once each on the same
commit, each run:

- given only the task prompt, the questions, README.md,
  `docs/guide/` and the skill, on VMs prepared as #37 lists;
- with no help (#37: no human message, no scripted-user message
  beyond the mode choice, approvals and the verbatim guided
  output, no file placed beyond the list, no retry of the same
  commit);
- installs iormesh from the release archive (guide chapter 3),
  traces the workload on `iom2` from `iom1` and builds a mesh
  that holds the workload's cross-service edges;
- answers at least 8 of the 10 questions correctly;
- within 150 agent turns and 60 minutes of wall time;
- runs no command that the latest approved explanation did not
  name — in guided mode, the agent runs nothing itself and the
  harness types exactly the commands it named.

A failed cell becomes a task carrying its transcript, and is rerun
only after a change to the docs, the skill or iormesh. The
questions are never reworded, dropped or re-scored to make a run
pass. Both model providers see all command output from the VMs
(#37, "Data"): the trial runs on synthetic data only.
